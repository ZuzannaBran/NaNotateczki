NaNotateczki — wdrożenie backendu zgodnego z klientem

Kontrakt:
- logowanie przez username (3–32 znaki ASCII, cyfry, podkreślenie), bez e-maila;
- migracja 0003_username.sql zachowuje UUID kont oraz nadaje stare loginy;
- rejestracja i nowe hasło: 8–128 znaków; logowanie: 1–256 znaków;
- zmiana hasła unieważnia również JWT i WebSocket przez auth_version;
- wymagana migracja 0002_auth_version.sql, poza 0001_initial.sql.

Aktualizacja:
1. Wykonaj i zweryfikuj backup PostgreSQL i data/ zgodnie z README.md.
2. Przenieś pakiet server/ do /srv/nanotateczki/ bez nadpisywania .env,
   data/ i web-dist/. Aktualizacja samego api/ nie dostarcza migracji.
3. Uruchom scripts/apply-migrations.sh, potem docker compose build api.
4. Dla testu HTTP uruchom:
   docker compose -f compose.yaml -f compose.local.yaml up -d api
   python3 scripts/smoke-local-api.py
5. Klienta lokalnego uruchom z katalogu aplikacji:
   bash tool/run_local_backend_web.sh
   Na innym komputerze otwórz najpierw tunel SSH opisany w README.md.

Wdrożenie publiczne:
- ustaw domenę i Cloudflare Tunnel zgodnie z README.md;
- uruchom compose.yaml z compose.public.yaml;
- zbuduj Web z --dart-define=BACKEND_URL=https://api.TWOJA_DOMENA;
- opublikuj build/web/ jako /srv/nanotateczki/web-dist/;
- sprawdź rejestrację zgodnie z ALLOW_REGISTRATION w .env.

Nie używaj docker compose down -v. Lokalny wariant Compose włącza
rejestrację i port HTTP tylko na loopback; pomiń go przy wdrożeniu domeny.
